# Module 25 全局精英副本扫荡侦察记录 (2026-11-10)

## 目标
不进入精英副本城镇，直接扫荡全部精英副本并自动出售装备。

## 协议链路 (线上实测)
1. `25/0 get_status` 请求 `[Int 精英副本ID, Uint32 PrevAct]`
   - 返回 `"FP"` 头 + 子关卡列表 `[Int mission_id, Int16 level, Int8 type]`，
   - 例：169 → 433/431/432（level 27, type 1）；166 → 448(level 31,type 3)/447(level 31,type 1)。
2. `25/1 start_practice` 请求 `[Int 子关卡ID, Int16 count, Int8 auto_sale, Uint32 PrevAct=0x00190000]`
   - `count=1, auto_sale=1`，响应首字节 0=成功、1=体力不足、2=背包满、3=队列中。
3. 例：169→433、166→448、167→450、168→614 均返回 `result=0`。

## 已验证结果
- **ncs s0 服务端上下文**：全局 190 副本循环成功扫荡 2 个（166→448、464→615），随后网关 EOF 重连中断。
- **手动临时会话**：登录后立即 `status→start` 稳定成功（即使加入 3s 延迟）。
- **qq s0 例程上下文**：多次运行 `swept=0`；qq 体力从 0 恢复到 10 后仍为 0，排除体力因素。

## 已知坑
- Module 25 的请求尾 4 字节 PrevAct 会被 RoleSession 强制覆盖为 `LastActionID`（mod==25 自动追加）。
  连续 `status` 时会自引用 `0x00190000`，服务端静默丢弃；已加入 `RoleSession.SetLastActionID` 并逐副本重置锚点。
- 网关 EOF 重连会中断批量扫荡；循环已加入等待 Active + 刷新锚点。
- qq 例程上下文与手动会话的差异仍未定位：疑似例程前置动作（活跃度面板/心跳）改变了服务端场景上下文。
